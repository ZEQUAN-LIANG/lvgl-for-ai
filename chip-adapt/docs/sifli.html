SiFli SDK 图形能力（LVGL）

SiFli-SDK v2.5.1 的显示引擎、编解码引擎与 2D 加速引擎，面向 LVGL 9.4 应用；黄山派 SF32LB52x 为重点。

本页是混合索引：能力矩阵 + 关键事实 + 真源路径。不复制大段实现，不写性能结论；涉及快慢时只记录「走硬件 / 走软件」的路径事实和官方定性描述。除特别说明外，SDK 路径相对 chip-adapt/vendor/sifli-sdk/，仓库路径相对仓库根。开始操作前先读 chip-adapt/README.md；SDK 未下载时，下方 SDK 链接不可用。

1. 芯片家族与定位

SDK v2.5.1 支持 52x、55x、56x、57x、58x 五个芯片家族。本仓库当前只导出黄山派 SF32LB52x；其他家族列在这里用于判断能力差异，不表示已经支持多芯片导出。

2. 显示引擎：LCDC

LCDC 把 SPI、QAD-SPI、QSPI DDR、DBI、DPI、DSI、JDI 等物理接口统一成同一套送图接口。它支持单色背景、图层 0、图层 1（52x 不支持图层 1）、图层 alpha 混叠、ROI、帧同步/行同步，以及同步和中断两种送数方式。

2.2 DBI / DSI / DPI / JDI 的区别

DBI、DSI、DPI 是 MIPI 的三种显示接口；JDI 是 Japan Display Inc. 的专有行列驱动接口，不是 MIPI 标准。关键差异在「有没有命令通道」和「面板侧有没有 GRAM / T-CON」：DBI 与 DSI Command 先把像素写进面板的 GRAM，DPI 连续送像素，JDI 走专有的行列驱动时序。

图：从 LCDC 到面板的路径。DBI 和 DSI Command 先写面板 GRAM；DPI 连续送像素；JDI 走专有行列驱动时序。

2.4 黄山派 CO5300 链路

  • 屏幕：CO5300，390x450，QAD-SPI 4 数据线；面板带 GRAM，TE 打开，LCDC 使用 HAL_LCDC_SYNC_VER 同步。
  • 板级开关：CONFIG_BSP_USING_EPIC=y、CONFIG_BSP_USING_LCD=y、CONFIG_LCD_USING_TFT_CO5300=y、CONFIG_BSP_USING_TOUCHD=y，见 board.conf。
  • 52x 没有压缩 framebuffer，默认走 LCD_FB_USING_ONE_UNCOMPRESSED：一个 PSRAM 全屏 framebuffer + SRAM partial 绘制缓冲。开启 CONFIG_LV_FB_TWO_NOT_SCREEN_SIZE=y 时是两个 partial 缓冲，每个 LV_FB_LINE_NUM 行，不是两个全屏 FB。
  • 刷新路径：LVGL 先画到 SRAM partial buffer → drv_lcd_fb_write_send() 合并脏区并拷贝到 PSRAM framebuffer（部分拷贝由 EPIC 的 drv_epic_copy 完成）→ LCDC 在 TE 同步下送 CO5300 GRAM。
  • 真源：SDK: middleware/lvgl/lv_drivers_v9/lv_lcd.c（flush / flush_wait / rounder / render_start）、SDK: rtos/rtthread/bsp/sifli/drivers/drv_lcd_fb.c、SDK: customer/peripherals/display/co5300/co5300.c。

3. 编解码引擎

SiFli 的「编解码」在 LVGL 侧主要指 EZIP / EZIPA 硬件解压，以及 JPEG、PNG、GIF、视频的软件或硬件路径。52x 没有硬件 JPEG 解码；EZIP 是 52x 上大图、背景和动画帧的主要硬件路径。

3.1 EZIP / EZIPA

  • EZIP 是 SiFli 私有压缩格式。HAL 支持 AHB 和 EPIC 两种输出：AHB 模式把解压结果写到指定内存，EPIC 模式把解压结果直接送入 EPIC，由 EPIC 完成混叠和缩放；EZIP 不支持旋转。
  • AHB 模式下同一个 EZIP 硬件还支持 LZ4 和 GZIP4 解压；图像 EZIP 走 HAL_EZIP_MODE_EZIP。
  • EZIPA 是动画容器，基于 EPIC + EZIP 逐帧合成；SDK 文档常称「APNG」，但运行时代码解析的是私有 ezipa_hdr_t、帧表和动画控制表，不是标准 APNG chunk。
  • LVGL v9 的 EZIP 解码器由 LV_USE_DRAW_EPIC && LV_USE_EZIP 启用，注册在 SDK: middleware/lvgl/lv_drivers_v9/lvsf_img_decoder.c。变量源只给压缩数据打 LV_IMAGE_FLAGS_EZIP 标记，不做 CPU 解压；文件源在打开时装载到 PSRAM/SRAM 缓存，NOR MTD 上可通过物理地址直接映射，减少拷贝。
  • 绘制时 LV_IMAGE_FLAGS_EZIP 被映射为 EPIC_INPUT_EZIP，见 SDK: middleware/lvgl/lv_drivers_v9/sifli/lv_draw_epic_img.c；真正解压发生在 EPIC 混叠时，不在 lv_image_set_src()。
  • EZIPA 的 LVGL 控件在 SDK: middleware/lvgl/lvsf_v9/lvsf_ezipa.c，解码器在 SDK: middleware/ezipa_dec/ezipa_dec.c。

3.2 JPEG / PNG / GIF

  • 52x：没有硬件 JPEGD。LVGL v8 工程常用 CONFIG_LV_USE_SJPG=y（TJpgDec 软件解码）；LVGL v9 需要手动开 TJPGD 或 libjpeg-turbo，默认示例通常不开。
  • 57x：有 JPEGD，EPIC 输入格式支持 JPEG，可以把 JPEG 直接交给 EPIC 混叠；HAL JPEGD 也可输出 YUV420 到 AHB，供视频路径使用。
  • 58x：独立 JPEGDEC，EPIC 本身不吃 JPEG；ffmpeg 的 MJPEG 路径直接调用 jpeg_decode2。
  • PNG：LVGL 的 lodepng / libpng 软件解码，默认通常不开；官方推荐构建期把 PNG 转成 EZIP。
  • GIF：gif_dec 预编译库，CPU 软件解码；官方文档说明 GIF 不支持透明度。AGIF 示例在构建期把 GIF 交给 eZIP 工具转换。

3.3 视频

  • ffmpeg 路径：h264、h263、mjpeg 等视频编码，mp3、aac、opus、vorbis 等音频编码；封装支持 ogg、mp4。h264/h263 解码后是 YUV，52x/56x/57x 可以直接用 YUV420p 显示。
  • EZIP 视频：每帧单独 EZIP 压缩，不做帧间压缩，仍使用 mp4 封装；解码后拿到的是 EZIP 数据，UI 直接显示，硬件解压由 EPIC/EZIP 完成。
  • MJPEG 在 58x 上有硬件解码路径；文档中「MJPEG 只在 58x 硬件解码」的说法对 57x 不完全准确，代码里同时存在 57x 的 HAL_JPEGD 路径。以 SDK: external/ffmpeg/libavcodec/mjpegdec.c 和芯片寄存器定义为最终依据。

3.4 资源生成与加载

  • 构建期转换用 tools/png2ezip/ezip.exe。常用命令：ezip -convert x.png -rgb565 -cfile 2 -section ROM3_IMG -lvgl_version 9；-binfile 2 -binext .ezip 生成二进制文件。
  • -cfile 1 是像素格式 C 文件，-cfile 2 是 EZIP C 文件；小图可用 -dpt 1 直接转像素，大图用 -dpt 4 配合 -ers（2 的幂）控制解压缓冲。
  • 57x 的资源必须加 -winsize 2048；SDK 的 Env.ImgResource() 在 SOC_SF32LB57X 时会自动补上。
  • 运行时文件加载：lv_image_set_src(img, "A:/x.ezip") 需要 CONFIG_LV_USE_FS_POSIX=y 和盘符配置；文件模式节省内存，预加载到 PSRAM 的 dsc 模式占用更多内存。图片文件数据缓存池由 CONFIG_IMAGE_CACHE_IN_PSRAM_SIZE / CONFIG_IMAGE_CACHE_IN_SRAM_SIZE 配置。
  • 真源：SDK: docs/source/zh_CN/app_note/ezip_tool_usage.md、Help.txt、SDK: example/multimedia/lvgl/ezip_v9/src/main.c。

4. 加速引擎：EPIC

EPIC 是 2D 图形引擎。官方 HAL 文档列出的能力包括：两幅图 alpha 混叠、任意锚点旋转、缩放、一次操作内旋转后缩放、纯色/半透明填充、输入输出颜色格式自动转换、小数坐标混叠（55x 不支持）。它不负责画线、圆、多边形；单步渲染模式明确不支持这些操作，渲染列表模式才提供。

4.2 单步渲染（默认）

未开启 CONFIG_DRV_EPIC_NEW_API 时，LVGL v9 使用 SDK: middleware/lvgl/lv_drivers_v9/sifli/lv_draw_epic.c 的 draw unit。能派给 EPIC 的任务是白名单：

  • 矩形填充：纯色，或 2 个色标的水平/垂直渐变；带 alpha 或 mask 的填充。
  • 图片：普通混叠、缩放、旋转；EZIP/JPG/YUV 可以混叠/缩放，但不能旋转。
  • 字体：A2/A4/A8 位图字形；静态 A8 bitmap 直接使用。
  • 边框：只有无圆角、四边完整的边框才走 EPIC。

以下任务在单步模式下明确回退到软件绘制：圆角矩形、超过 2 个色标的渐变、渐变输出格式不受支持、带 recolor 的图片/图层、RGB565A8 带旋转/缩放、不支持的图片颜色格式、非完整边框或圆角边框、矢量字体。arc、line 的 evaluate 分支被 #if 0 关闭；shadow（BOX_SHADOW）、LETTER、TRIANGLE、MASK_RECTANGLE 没有 EPIC 分支，全部走 SW draw unit。

官方 SDK: example/rt_device/gpu/render_list_mode/README.md 示例明确支持 sf32lb52-lchspi-ulp；watch（LVGL v8）工程的 proj.conf 已开启 CONFIG_DRV_EPIC_NEW_API=y。驱动文档明确渲染列表不能用于 55x。驱动层还有 DRV_EPIC_DRAW_SHADOW（CPU 生成覆盖 mask + EPIC masked fill），但 LVGL v9 的 render-list draw unit 目前没有派发 BOX_SHADOW，所以 LVGL v9 的阴影仍走软件。

4.4 限制与不支持项

  • EZIP 不能旋转；EPIC 的旋转/矩阵变换不支持 EZIP、JPG、YUV 输入。
  • 52x 一次混叠的前景、背景、输出区域并集不能超过 EPIC_COORDINATES_MAX；有变形时上限 512，普通混叠 1024。
  • A4/A8 做 mask 时不能旋转或矩阵变换。
  • 镜像不能与旋转、缩放同时进行。
  • 52x 没有 JPEGD、L4、颜色矩阵、3x3 矩阵、A8/灰度输出；这些是 57x 的能力。
  • 52x 没有 GE2D、DMA2D、VGLITE；不要使用 52x 不存在的加速 API。

5. 官方推荐写法

官方推荐的 LVGL 应用不是从零写 lv_port_disp.c，而是复用 SDK 的 middleware/lvgl 适配层。适配层负责 LCD、触摸、按键、滚轮、FPS 统计；应用只写 UI。

5.1 工程结构

  • project/SConstruct：按 PrepareEnv → AddBootLoader → SifliEnv → PrepareBuilding/DoBuilding → AddFTAB → GenDownloadScript 组织。
  • project/SConscript：导入 SDK 根 SConscript，再导入 ../src/SConscript。
  • project/Kconfig：source "$SIFLI_SDK/Kconfig.v2" 与 rsource "Kconfig.proj"。
  • project/Kconfig.proj：应用私有配置项。
  • project/proj.conf：只写相对 board.conf 和 Kconfig 默认值的最小差异。
  • project/rtconfig.py：工具链/芯片/核/目标名；应用级可以是空文件，板级会提供默认值。
  • src/SConscript：用 Glob('*.c') + DefineGroup 收集应用源文件；新增子目录要在父 SConscript 显式导入。
  • src/main.c：应用入口。

配置优先级：proj.conf > board.conf > Kconfig 默认值；板级差异化可放在 project/sf32lb52-lchspi-ulp_hcpu/proj.conf，优先级最高。真源：SDK: docs/source/zh_CN/app_development/create_application.md、SDK: docs/source/zh_CN/app_development/build_and_configuration.md。

    rt_thread_mdelay(ms);
}
  • littlevgl2rtt_init("lcd") 内部调用 lv_hal_init()，初始化 LCD、触摸、按键、滚轮，并注册图片解码器和 FPS 统计；它不调用 lv_init()。
  • lv_init() 由 gui_lib_init() 在 RT-Thread 组件初始化阶段完成，通过 INIT_COMPONENT_EXPORT 注册；应用不要再调一次。
  • 主循环用 lv_task_handler()（lv_timer_handler() 的兼容别名），返回值作为 rt_thread_mdelay() 的延时。
  • 真源：SDK: middleware/lvgl/littlevgl2rtt.c、SDK: middleware/lvgl/littlevgl2rtt.h、SDK: middleware/lvgl/lv_drivers_v9/lvgl_drv.c。

5.3 多应用 / 多页面

  • 产品级 UI 用 GUI_APP_FRAMEWORK：gui_app_init(1)、gui_app_run("Main")，应用通过 BUILTIN_APP_EXPORT 注册。
  • 页面生命周期：on_start 创建控件/订阅服务；on_resume 启动 timer；on_pause 停止 timer；on_stop 退订/释放内存。
  • 参考 watch_v9（LVGL v9）和 SDK: example/multimedia/lvgl/watch（LVGL v8）。
  • 真源：SDK: docs/source/zh_CN/middleware/gui_app_framework.md、SDK: middleware/include/gui_app_fwk.h。

5.5 资源与缓存

  • 构建期优先用 Env.ImgResource() / ezip.exe 把图片转成 EZIP，放进 .ROM3_IMG 等资源段；小图可以用 -dpt 1 直接转像素，避免运行时解压。
  • 大图、可替换资源放文件系统或 SD 卡，运行时通过 lv_image_set_src() 加载；需要 CONFIG_LV_USE_FS_POSIX=y 和盘符配置。
  • 官方建议在页面的 on_resume() 把热图复制到 SRAM，冷资源留在 Flash/PSRAM。
  • 图片缓存分两层：LVGL 的 LV_IMG_CACHE_DEF_SIZE（条目数）和 SiFli 的 CONFIG_IMAGE_CACHE_IN_PSRAM_SIZE / CONFIG_IMAGE_CACHE_IN_SRAM_SIZE（解码数据缓存池）。

5.6 调试与测量

  • 串口 fps2 开关 FPS/CPU/EPIC 统计；日志每 2 秒输出一次，包含 FPS、CPU load、EPIC 占用、LVGL idle、cache miss。
  • 代码里可以调 set_display_fps_and_cpu_load(1) 和 lv_get_fps()；这些 API 在 SDK: middleware/lvgl/littlevgl2rtt.h。
  • 本页不给出测量值，也不比较快慢；量化结论以目标板实测为准。

6.3 与本仓库 chip-adapt 导出的关系

  • chip-adapt/sifli/export.py 负责复制 user/app 源码、生成 SCons 工程、调用 ezip.exe 生成资源 C 数组；导出产物在 chip-adapt/exports/<app>/，不写入下载的 SDK。
  • 资源由 user/app/<app>/assets.json 声明：冷图用 mode=ezip，旋转/缩放/热图用 mode=raw；导出器生成 src/app/<app>/assets.h、assets.c 和 app_assets_init()，并把缓存配置写进 project/proj.conf。
  • 导出的 src/main.c 是官方最小工程写法：littlevgl2rtt_init("lcd") → app_create() → lv_task_handler() 循环。应用入口是 void <app>_create(void)；src/app/app.c 先调 app_assets_init()，再调应用入口。
  • src/app/lvgl_ai_sdk.h 用 __has_include("littlevgl2rtt.h") 区分 SDK 构建与本地 headless 验证：SDK 构建拿真实头，本地验证拿 sim_sifli.h 桩。桩只用于验证，不代表 EPIC、触摸或真实刷新行为。
  • 应用必须按 LVGL 9.4 基线编写；导出器扫描 9.5/9.6-only API，发现时返回 unsupported_api，不生成会编译失败的工程。
  • 真源：chip-adapt/sifli/README.md、templates/src/main.c、templates/src/app/lvgl_ai_sdk.h。

7.2 应用约束

  • 按 LVGL 9.4 API 编写；不要使用 9.5/9.6-only API；版本门建议写 LVGL_VERSION_MINOR >= 4。
  • 屏幕 390x450；非 390x450 的设计需要自行适配布局。
  • EZIP 只能混叠/缩放，不能旋转；需要旋转的图片要先复制到 RAM，并避开 EZIP 输入。
  • 52x 没有硬件 JPEG；不要在运行时直接解大 PNG/JPEG，构建期转 EZIP。
  • 不要使用 52x 不存在的加速 API：LV_USE_VGLITE、GE2D、DMA2D、硬件 JPEGD。

7.3 验证顺序

导出与 headless 验证的完整命令见 chip-adapt/sifli/README.md；固件构建与烧录优先用 chip-adapt/sifli/host/README.md 的内部 host，官方 sifli-build-win / sftool skill 只在手动方式或通用 SDK 场景参考。headless 结果不代表真机 EPIC、触摸或刷新行为。
